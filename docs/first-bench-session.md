# מפגש ספסל ראשון (Bench) - צעד אחר צעד

המטרה: לחבר את האפליקציה לרחפן האמיתי **על השולחן, בלי מדחפים**, לראות שהנתונים מגיעים, ולגלות מה עוד צריך להגדיר.
שום שלב כאן לא דורש חימוש. אם משהו לא ברור - עצור ושאל.

## לפני שמתחילים

- **הסר את המדחפים.**
- הרחפן מחובר לסוללה או לספק כוח, ה-Pi דלוק, והמחשב באותה רשת Wi-Fi (או ב-Tailscale).
- Mission Planner יכול להיות פתוח במקביל - האפליקציה לא מפריעה לו.

## שלב 1 - מלאי של ה-Pi (קריאה בלבד)

על ה-Pi (SSH רגיל, או מסך ומקלדת):

```bash
bash probe.sh > probe.txt 2>&1
```

(את `probe.sh` מעתיקים מהתיקייה `pi/deploy/` במאגר.) הסקריפט **לא משנה כלום**.
הוא מדפיס: גרסת מערכת ההפעלה, כלי המצלמה (`rpicam-*`), שמות השירותים, הגדרות mavlink-router, ממשקי רשת,
התקני USB (כדי לזהות את מודם ה-ZTE) ו**טביעות האצבע של מפתחות ה-SSH של ה-Pi**.
שמור את הפלט. נצטרך אותו כדי למלא את ההגדרות, ואפשר לשלוח אותו אלי (אין בו סיסמאות, אבל יש שמות מארח וכתובות).

## שלב 2 - מפתח SSH (מומלץ במקום סיסמה)

ב-Windows (PowerShell):

```powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\x500_ed25519
type $env:USERPROFILE\.ssh\x500_ed25519.pub
```

את השורה שמודפסת מוסיפים ב-Pi לקובץ `~/.ssh/authorized_keys` של המשתמש שלך.
(זה שינוי שאתה עושה ידנית ב-Pi. האפליקציה לא עושה אותו.)

## שלב 3 - הגדרות באפליקציה

**הגדרות → חיבור:**
- כתובת ה-Pi: למשל `x500pi` או כתובת ה-Tailscale שלו
- משתמש SSH: המשתמש שלך ב-Pi
- אימות: "מפתח SSH", קובץ: `C:\Users\<אתה>\.ssh\x500_ed25519`. אם יש למפתח passphrase - לחץ "שמור סיסמה / passphrase"
- נתיב תקשורת: **Wi-Fi** לפגישת הספסל הראשונה
- שם מארח צפוי: `x500pi`

**הגדרות → MAVLink:** השאר "מנהרת SSH" אל `127.0.0.1:5760`. כך האפליקציה מגיעה ל-mavlink-router דרך SSH
בלי לפתוח פורט ברשת. אם `probe.sh` מראה ש-mavlink-router מאזין בפורט אחר, עדכן כאן.

**הגדרות → Pi:** מלא את שמות השירותים של ה-watchdog ושל הקופסה השחורה, ואת נתיב קבצי הלוג
(למשל `/var/log/x500/*.log`), לפי הפלט של `probe.sh`. עד שתמלא אותם, הבדיקות האלה יופיעו כ-UNKNOWN עם הסבר.
את `x500-preflight` / `x500-status` הוסף ל"סקריפטים קיימים" רק אחרי שווידאת שהם לקריאה בלבד, וסמן `enabled: true`.

**פרופיל** (בסרגל העליון): **ספסל (Bench)**.

## שלב 4 - התחברות ואימות מפתח השרת

1. לחץ **התחבר**.
2. בחיבור הראשון יופיע חלון "אימות מפתח השרת של ה-Pi" עם טביעת אצבע `SHA256:...`.
3. השווה אותה לשורה המתאימה (בדרך כלל ED25519) בסוף הפלט של `probe.sh`, או הרץ ב-Pi:
   `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`
4. רק אם הן **זהות לגמרי** - לחץ "הטביעה זהה - סמוך ושמור".

## שלב 5 - הרצת בדיקה

לחץ **הרץ בדיקה** וחכה כ-10 שניות (איסוף מה-Pi וקריאת פרמטרים). מה אמור להופיע בספסל:

- **Pi, תקשורת, HEARTBEAT, זיהוי בקר הטיסה, מצב חימוש** - אמורים להיות PASS. אם לא, קרא את ההסבר בחלונית התחתונה.
- **Pre-arm / GPS / EKF** - ייתכן FAIL או WARN על השולחן (למשל אין קיבוע GPS בתוך מבנה, או אין מקלט RC). זה מידע, לא תקלה של האפליקציה.
- **בדיקות חימוש (ARMING_CHECK / ARMING_SKIPCHK)** - אם כיבית את בדיקת ה-RC כי אין שלט, הבדיקה תיכשל עד שתרשום במפורש
  בפרופיל `"allowed_skipped": ["RC"]`. כך ההחלטה גלויה ומתועדת.
- **סוללה ותצורה** - "סוג סוללה ומספר תאים" ו"Failsafe/RTL/Fence מול פרופיל צפוי" יהיו UNKNOWN עד שתגדיר אותם
  (ראו שלב 7). בספסל הן לא חוסמות. בטיסה הן כן.

## שלב 6 - וידאו (אופציונלי, אחרי התקנת MediaMTX)

אם עדיין לא התקנת MediaMTX, ראו [pi/README.md](../pi/README.md). אחר כך:
1. **הגדרות → Pi → שירות MediaMTX** = `mediamtx`
2. **הפעל וידאו**. האפליקציה בודקת שהרחפן לא חמוש, מחילה 640×480@15, ופותחת RTSP דרך מנהרת SSH.
3. בלשונית "טלמטריה" תראה CPU וטמפרטורה של ה-Pi. בדוח תופיע טבלת "וידאו - מדידות ביצועים".
   **אל תעלה רזולוציה או FPS לפני שמדדת** (ראו [docs/video.md](video.md)).

## שלב 7 - הגדרת פרופיל הטיסה (לפני שימוש בפרופיל טיסה)

**הגדרות → כללי → פתח תיקיית פרופילים** ואז ערוך את `flight.json`:
- `battery.chemistry` ו-`battery.cells` (למשל `"LiPo"` ו-`4`). האפליקציה לא מנחשת אותם.
- `expected_params` - הערכים שאתה **מצפה** שיהיו ב-failsafe, ‏RTL ו-fence. לדוגמה:

```json
"expected_params": {
  "failsafe": {"FS_GCS_ENABLE": {"eq": 1}, "BATT_FS_LOW_ACT": {"in": [2, 3]}},
  "rtl": {"RTL_ALT": {"min": 1500, "max": 6000}},
  "fence": {"FENCE_ENABLE": {"eq": 1}}
}
```

הערכים בדוגמה הם **רק דוגמה** - הכנס את הערכים שאתה החלטת עליהם. הערכים הנוכחיים בבקר מוצגים בפרטי הבדיקה,
אבל האפליקציה לא תסמן אותם כ"מאומתים" בלי פרופיל צפוי. ב-ArduPilot 4.7 חלק מהשמות השתנו (למשל `RTL_ALT` → `RTL_ALT_M`, במטרים).
כל פרמטר שתכתוב כאן נקרא מהבקר (קריאה בלבד).

## שלב 8 - דוח

לחץ **ייצא דוח**. נשמרים קובץ HTML (לקריאה) וקובץ JSON. הסיסמאות והמפתחות מוסרים מהם.
שלח לי את הדוח ואת פלט `probe.sh` - כך נוכל לכוונן את הבדיקות לרחפן שלך.

## אם משהו לא עובד

| תסמין | מה לבדוק |
|---|---|
| "הזדהות נכשלה" | המפתח הציבורי נמצא ב-`authorized_keys`? משתמש נכון? |
| "SSH port forwarding ... refused" | ב-`/etc/ssh/sshd_config` של ה-Pi: `AllowTcpForwarding` לא `no`. ה-mavlink-router מאזין ב-`127.0.0.1:5760`? |
| HEARTBEAT לא מגיע אבל SSH עובד | הפורט של mavlink-router (ראה `probe.sh`, ‏`ss -ltn`), ו-mavlink-router פעיל |
| הודעות מבקר הטיסה חסרות (UNKNOWN) | ייתכן `SYSID_ENFORCE=1` / ‏`MAV_OPTIONS` bit 0 - הבקר מתעלם מבקשות של sysid שאינו תחנת קרקע (תראה אזהרה בבדיקה "זהות האפליקציה") |
| "מפתח השרת השתנה" | אם התקנת מחדש את ה-Pi - הגדרות → חיבור → "שכח את מפתח השרת", ואמת שוב. אחרת - עצור ובדוק. |
